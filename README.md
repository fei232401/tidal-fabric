# tidal-fabric

> **训推混部集群里，"让卡"不等于"让路"。**
> 训练 NCCL 大象流与推理 KV 搬运流共享同一张 RDMA 无损网络时，GPU 侧的让渡决策并不感知网络后果。
> 本仓库用 chunk 级确定性离散事件仿真量化这个盲区，并提出**让渡前的静态死锁预检**。

`Python` · 确定性离散事件仿真 · `25 测试` · 无外部依赖（stdlib）

---

## 1. 它解决什么问题

训推混部里常见一个动作：推理高峰来了 → 让出 GPU 给推理。但如果训练还在跑，它的 NCCL 集合通信仍在网络上。

于是出现两条独立的伤害路径：

1. **带宽争抢**：训练的大象流挤压推理的 KV cache 搬运流 → 推理 TTFT/SLO 恶化；
2. **路由重构引发死锁**：让渡过程会触发集合通信 ring 重建 → 流与自适应路由的新映射可能构成 **PFC 死锁环**（无损网络特有，一旦成环整条链路停摆）。

第 2 条是"适得其反"的终极形态：为了救推理而做的让渡，反而把推理彻底打挂。

## 2. 核心结果（仿真）

| 发现 | 数值 | 说明 |
|---|---|---|
| 共置使 KV 搬运 SLO 违约 | **1.5% → 23.9%（16×）** | 而训练仅慢 **1.04×** —— **伤害高度不对称** |
| 源侧限速（让渡） | **23.9% → 4.5%** | 呈剂量响应 |
| PFC 反压计数 | **3280 → 106** | 限速让渡后反压链显著缓解 |
| 死锁率 vs 自适应路由比例 | **0% → 67% → 75% → 100%** | **单调上升**：死锁 = 让渡重哈希 × 非最短路由的交互 |
| 静态预检规避率 | **100%**（全比例 0 死锁） | KV 受害流 pending 7.8 → 0 |
| 预检单次成本 | **12.5 µs** | 对照：业界 watchdog 事后恢复 **100–400 ms** |

> **关键对比**：业界的做法基本都是**事后 watchdog**——等死锁发生再检测、再恢复，代价是那 100–400 ms 里的流量损失。
> 本方案把检查**挪到让渡之前**：用缓冲依赖图做一次 `O(V+E)` 的环检测，**事前规避**，且无损。
> 这不是"同一个检查跑得更快"，而是**从"事后恢复"变成"事前规避"**。

## 3. 静态死锁预检怎么工作

```
   让渡请求到达
        │
        ▼
   构造缓冲依赖图  G(V, E)        V = 网络缓冲/队列, E = "依赖等待"关系
        │
        ▼
   环检测  O(V+E)                 存在环 ⇒ 该让渡会导致 PFC 死锁
        │
        ├── 无环 → 允许让渡
        └── 有环 → 拒绝 / 改换路由方案（不进入让渡）
```

单次 **12.5 µs**，相对让渡动作本身的开销可忽略，因此可以放在决策路径上同步执行。

## 4. 四个研究问题与结论

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 让卡不让路：训练大象流挤压推理 KV 搬运会造成多大伤害？ | 共置使 KV 违约升至 **16×**，而训练仅慢 1.04× —— **伤害不对称** |
| Q2 | 通信让渡能否恢复 SLO？训练侧代价多大？ | 源侧限速让渡呈剂量响应：**23.9% → 4.5%**；发现 cap 门槛效应与 PFC 消失链 |
| Q3 | 让渡引发的路由重构是否可能造成 PFC 死锁？能否事前规避？ | 死锁率随自适应路由比例**单调升至 100%**；**静态预检 100% 规避** |
| Q4 | 并发让渡的竞态（缩容撞 collective / 双向双花 / 视图滞后）怎么消除？ | 步边界安全点协议 + 声明式目标收敛；视图滞后下存在**条件性伤害**（快潮汐 **−31%** 进度） |

## 7. 诚实边界（重要）

1. **PFC 死锁在真机上不可复现**——需要可配置的 RoCE 交换机组网，本项目不具备。因此死锁相关结论全部来自 **chunk 级确定性仿真**，并以业界公开案例作为锚点。
2. **DCQCN 等协议调参属于深水区**，本仓库只到**原理级**，不做协议级调优。
3. **没有真实生产流量**：流量模型为合成潮汐曲线 + 公开数据集形状代理。
4. 网络侧混部的干扰研究是相对空档（算力侧已有大量工作），因此多为设计权衡而非照搬既有方案。
